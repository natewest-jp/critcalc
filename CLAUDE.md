## Data Architecture

### Character Data

123 character JSONs in `src/lib/data/characters/`, generated **in-repo** by `scripts/ingest-character.mjs` from the `genshin-db` devDependency (the old external generator is retired). Canonical type is `CharacterData`. Full payloads are code-split and lazy-loaded (`characterData.ts`); the eager index (`characterIndex.generated.ts`, regenerated on predev/prebuild) carries identity fields **plus derived capability summaries**.

### The Capabilities Layer (`src/lib/capabilities/deriveCapabilities.ts`)

Capabilities (heal/shield/off-field DMG/res shred/buffs/cleanse/grouping/…) are **derived from effects and tags, never hand-maintained**, each with provenance (source ability, constellation gate, runtime-condition caveats). Consumed by the Team Builder facets, the build-time index, and the audit. Runtime-import-free so Node scripts execute it directly.

## Coding Conventions

- **No speculative abstractions**; flag data gaps with `// TODO: data gap — [field]`
- SSR/hydration safety: deterministic default first paint → onMount restore (pattern in memory `project_rotation_planner_ssr_fix`)
- **Sub-pixel rendering laws (2026-08-06 — /styleguide § Laws holds the full text):** alpha belongs in the **paint** (translucent `background-color`/`fill-opacity`), never element `opacity`, on anything transform-placed — WebKit rasterizes an opacity subtree at rounded coordinates and it visibly dances. Symbol marks are **inline geometry**, never unicode characters (engines pick different fallback faces at different sizes). Centering a label centers its **box**, not its **ink** — measure with `scripts/probe-ink-centering.mjs` and tune optical nudges against **Chrome**, since WebKit snaps glyphs to whole pixels and its offset moves with layout position
- Avatars: `getAvatar(id, preferNewfit, size, traveler)` — availability manifest (`hasAvatar`) prevents SSR'd 404 imgs (prerender fails on them); regenerate via `npm run generate-newfit`
- **A visually-hidden input's LABEL must be positioned (2026-08-17).** `.check input` / `.toggle input` are `position: absolute`, so with no positioned ancestor they resolve against whatever is `relative` far above — which let them ESCAPE an intervening scroll container and hold a page in a scroll nothing visible accounted for. Both labels carry `position: relative` now. ⚠ Latent for as long as they have existed; only observable once something started clipping.
- **`--tool-pad-bottom` is `1.5rem` (2026-08-17), and the 24px it gave back was SPENT** on `AURA_PLOT_H` 56 → 80. ⚠ It is three tools' money — both viewport-fit surfaces subtract it — and the planner's chart frame lives in a measured `viewport − 300px` of fixed page, so at 1080p a heavy four-character rotation was already ~30px into a page scroll BEFORE the trade. ⛔ Don't grow the plot again without naming where the pixels come from; the next 24 come out of track rows. ⛔ And don't make it viewport-derived — `auraPlotH` rides the PNG snapshot, so two readers would export different charts of one rotation.
- **Page meta lives in ONE map (launch hardening, 2026-08-14 — `6f4b71f`):** every title, description, canonical and `og:`/`twitter:` tag comes from `src/lib/seo.ts`, rendered once by `SeoHead.svelte` in the ROOT layout. ⛔ **Never give a page its own `<svelte:head>` title** — `<svelte:head>` does not dedupe, so a layout tag plus a page tag emits two `<title>`s and two of every `og:` tag, and which wins is left to each scraper (invisible locally, invisible in tests, visible only once a link is public). ⚠️ **A new route needs TWO entries: `seo.ts` and `static/sitemap.xml`.** `OG_IMAGE` is versioned (`-v1`) because `/assets/*` is immutable-and-add-only _and_ platforms cache `og:image` by URL — a redraw ships as `-v2`, never an overwrite
- **The notation path is length-capped:** `MAX_NOTATION_CHARS` (16 KiB, in `tokenizer.ts`) is enforced by both `decodeRotation` and the CodeMirror editor, so the two entry points cannot drift. It is a safety guard, not a product limit — a hostile `?r=` link used to freeze or OOM the _recipient's_ tab. ⛔ Don't add semantic caps ("nobody writes ten Qs") to bound cost: that is a verdict, which the tool constitution forbids, and per-token limits are both restrictive and incomplete. Fix the algorithm instead. Full defect list, measurements and what is still open: `docs/parser-hardening-2026-08-14.md`
- **Errors have TWO surfaces and they catch different things:** `src/routes/+error.svelte` handles SvelteKit's routing/load failures (chiefly 404, and it renders outside the scene because an unmatched URL matches no route group), while `<svelte:boundary>` in `(tools)/+layout.svelte` catches a throw during component **render**, which `+error.svelte` does not see. ⚠️ Conflating them is how you come to believe you are covered when you are not
- Gates before any commit: `npx vitest run` (lint/parse/derivation/index-drift), `npm run check`, `npm run lint`

### Commits

- **The type vocabulary extends conventional commits.** Standard: `feat` `fix` `refactor` `perf` `test` `docs` `chore` `revert`. Three are ours and are NOT interchangeable with `feat`/`chore`: **`tune`** — adjusting hand-tuned VALUES, not behavior; **`polish`** — refining an existing surface, no new capability; **`experiment`** — exploratory direction work, usually on an `experiment/` branch. Scope names the area: `(tools)` `(bench)` `(planner)` `(landing)` `(color)` `(probe)` …
- **`tune(nate)` means Nate's own value pass, landed verbatim.** Those numbers are his measurements, not derivations — never "correct" or regenerate them (memory `feedback_expose_tuning_knobs`).
- The subject names the change in the project's voice; **the body says WHY**, including what was tried and rejected.
- **Feature branches merge with `--no-ff`**, message `Merge <branch> — <summary>`. ⚠️ The MERGE commit is the hash worth citing later, not the branch tip — that is what memory notes reference.
- **Push only when asked**, and never commit straight to `main` for feature work.

## Verification Policy

**Prefer running existing checks over writing new verification code.**

- `npm run check` — svelte-check
- `npm run test` — Vitest (parser/IR, capability derivation, character lint, codec roundtrips, timeline projections)
- `npm run lint` — prettier + eslint (incl. the `condition-shape` and caveat-style rules)
- `npm run build` — the production build is the real gate; **never verify against dev only**
- `npm run test:e2e` — Playwright at the browser surface, Chrome + WebKit (`e2e/`, ~74 tests per engine — `npx playwright test --list --project=chrome` for the current count). Builds and serves its own preview every run, so it cannot measure a stale server. ⏱️ **A PRE-MERGE GATE, NOT A PER-ROUND ONE** (⚓ Nate 2026-08-09): the cross-engine run costs ~6 minutes of wall clock and blocks the session, which is too expensive between iterations. Per round run vitest / check / lint / build (~30s together); run this before a merge, or when a change plausibly breaks the browser surface in a way those cannot see (scene/GL, transitions, portals, the band DOM, `backdrop-filter`). **Say in the commit when it was skipped, and which commit last ran green.** A single spec is cheap — `npx playwright test e2e/x.spec.ts --project=webkit`, ~20s. Variants: `test:e2e:chrome`, `test:e2e:webkit`, `test:e2e:ui`, `test:e2e:storm` (the slow cross-engine nav storm, `@storm`-tagged and excluded from the default run), `test:e2e:report`. 🐛 **Read the "N passed" line, not the exit code** — an UPSTREAM Chrome shutdown bug ([playwright#39753](https://github.com/microsoft/playwright/issues/39753), unfixed through 1.62.1) intermittently hangs worker teardown, so the process exits 1 with everything green. Don't bisect our specs for it (details in `playwright.config.ts`)
- Data validation lives in Vitest (`characterLint.test.ts`, `characterIndex.test.ts`) plus the `scripts/audit-*.mjs` reports — there is **no** `validate:data` script
- **`orphanedSchema.test.ts` (2026-08-15) fails when authored data has NO consumer** — the class that produced nine bugs in one day (`factionBonuses`, the five `infuse` effects, `shield` windows, variant `effects`, `summons[1]`, `noICD`, Citlali's `onState`, Hu Tao's `onStanceEnd`, onReaction self/active). ⚠️ It matches property **ACCESS**, never any mention, because a type declaration must not count as a consumer. On failure: wire it, retire it, or add it to `INERT` **with a reason** — ⛔ never a bare entry. ⚠️⚠️ It **cannot see PARTIALLY-wired data** (an `infuse` effect reached the Team Builder and was missing only from the parser), so a green run is not proof; the per-consumer pass in `docs/curation/orphaned-schema-audit.md` narrows that and is manual. Read memory `orphaned_schema`

Do not write a script to answer something readable in the source, documented in the SvelteKit/Vite docs, or already covered above.

If you need to observe runtime state, use an inline command (`node -e`, `curl | grep`, `npm run build && grep build/`) rather than creating a file. If a file is genuinely unavoidable, write it to `scratch/` (gitignored), run it, report the finding, and **delete it in the same turn. Never commit a one-off probe** — `scripts/probe-*.mjs` is a retired pattern, not a place to add to.

**Promote to a permanent check only when:**

- it caught a real, observed bug, AND
- the assertion survives unrelated refactors.

Propose the promotion and wait for approval; don't add spec or test files unprompted. When a promotion IS approved, it goes in `e2e/` (browser-level) or beside the module as a Vitest file — never back into `scripts/`.

**Writing an e2e spec** — three traps that have each cost real time, all documented at their site in `e2e/fixtures/critcalc.ts`:

- `addInitScript` re-runs on **every** navigation including `reload()`, so the `seed` fixture only fills keys that are absent. Seeding unconditionally makes a reload-then-assert test measure the seed instead of the app.
- `hasText` matches `textContent`, not rendered text: a button leading with a `<Mark>` SVG has whitespace first, so `/^Save/` never matches — and the uppercase you see is CSS `text-transform`, a separate trap.
- The nav-storm spec needs `--workers=1`. Concurrent headless browsers each driving the GL scene starve each other's rAF, which looks exactly like the transition bug it hunts.

**Calculation work:** when verifying a damage or buff figure, add it to the regression fixtures rather than checking it once and discarding the script.

**Visual and rendering work** (canvas instruments, the WebGL scene, gradients, SVG filters, typography): do not write verification scripts. Build it, describe what changed, and let Nate look at it.

**Safari: assume nothing is verified until Nate has checked it manually.** Playwright WebKit catches thrown errors, not rendering or performance differences.
