**Systemic bug found + fixed 2026-07-15 — unreachable Hold variants.** A variant is selected ONLY by matching a notation token against its `input` (`resolveAbilityTiming`/`resolveEQCastTime`/`resolveEffectiveCharges`); an input-less variant is dead data — the parser falls back to the base ability. **5 chars had input-less Tap/Hold pairs where `hE` silently rendered the shorter Tap cooldown + base frames/effects: candace, diona (Hold cd 15), razor (10), shenhe (15), venti (15).** All 5 FIXED: added `"input":["hE"]` to the Hold variant (canonical pattern = alhaitham), removed the redundant input-less 'Press' variant (its cd = base). Hold cds verified vs gcsim (diona 360/900, razor 6/10 pre-a1CDReduction, shenhe 10/15, venti 360/900). None needed a CD modifier besides Candace C4.

**New lint rule `variant-unreachable` (characterLint.ts) — now `strict` (2026-07-15).** Fires when a skill/burst variant customizes cast behavior (frames/cooldown/cooldownModifiers/energyCost/charges/behavior) but has no `input`. Guards against recurrence. Flipped from `warn` → `strict` once all flagged variants were triaged; `UNREACHABLE_VARIANT_EXEMPT = {'durin'}` downgrades Durin's deferred dual-form placeholders to `warn` (visible reminder). Any NEW input-less castable variant on a non-exempt character now FAILS CI.
