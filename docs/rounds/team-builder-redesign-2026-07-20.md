**Team Builder reevaluation session (2026-07-20, Nate + Fable→Opus). Plan APPROVED; implementation in progress. Supersedes the "feature-complete, done" framing in `docs/rounds/team-builder-tool.md`.** The full execution plan (6 phases, file-level) was a Claude plan file outside the repo and was not kept.

**Why:** the tool shipped feature-complete (`3742300`) but its front door is just a full-page character grid — it reads like the planner's Character Selector, undersells the question-indexed thesis, and doesn't reward wide screens the way the other two tools do.

**"One team, two rooms":** the Team Builder is where you _deliberate about_ a team; the Rotation Planner is where you _run_ it. Bridge = the team object over URL (`?team=`).

**Locked architecture (three-zone workspace, echoing the planner's left-edge/tracks/composer grammar):**

- **Bench — left-edge stacked column:** 4 team slots as portrait cards + resonance + coverage checklist (borrows Imaginarium Theater capability icons — Nate to source), "Send to Rotation Planner →" pinned at bottom. Coverage gaps are CLICKABLE → drive the Source filter. (Rename `TeamStrip.svelte`→`Bench.svelte`.)
- **Source — center, tabbed Atlas / Roster:** Atlas (default front door) = question-indexed capability cards ("Off-field Pyro DMG — 14 providers, 6 in your roster", per-element pips) built from the eager index (no full payload loads). Roster = the character grid + ownership ledger. Card click pivots to filtered Roster. Atlas splits into "your team provides"/"gaps" ONLY when a team exists.
- **Stage — right:** docked Detail (was modal) + rebuilt Compare. This is what rewards wide screens (Source + Stage expand to fill).

**Compare rebuilt (Nate's flagged priority):** stacked timing bars on ONE shared ruler, reusing the planner's REAL bar language — `barPhases.ts` segments, `elementColors`, 3-edge cooldown ghost, `computeSummonTicks` tick markers. Characters are ROWS within each capability group (A's Skill stacked over B's) → 4-way grows vertically, plain Stage scroll, NO takeover (respects the three-panel system). Replaces the from-scratch `.cmp-uptime` flex glyph.

**Audition mode:** an occupied Bench slot's "Audition" flips the Stage into Compare with the incumbent pinned as anchor row; commit a candidate → swaps the slot. Compare works Bench-free too.

**Ownership ledger:** NEW `ownership` store (`critcalc:ownership`, `Record<id,'owned'|'wishlist'>`, absence=neither) alongside `constellations`. One-time migration: any explicit constellation entry ⇒ owned. Setting a constellation implies owned (enforced at DetailCard call site, not store coupling). All/Owned/Wishlist views; wishlist badge in Compare. Fixes today's implicit-C0 ≡ not-owned pollution of "mine" mode.

**Planner goes non-modal too (the `docs/rounds/design-principle-nonmodal-tools.md`):** clicking a portrait opens the SAME shared `CharacterGrid` component layered over the timeline from the portrait edge — NOT a modal. Planner's Source = identity-filtered Roster grid only (no Atlas, no ownership). Per-slot ⇄ swap icons RETIRED; one **"Explore alternatives →"** button (Nate-confirmed wording) in the vacant bottom-left of the portrait area (notation composer starts at portrait's right edge) sends the whole team to the TB. Old single-char `?replace=` pre-seed RETIRED → whole-team `?team=` + Atlas-suggested-from-tags.

**Loadout resolution — ⚠️ STILL UNBUILT as of Phase 4 (the below is the PLAN; Phases 1-4 never touched loadout in the TB — no loadout editing exists on the Bench/Detail yet; needs a future phase or a Phase-5 rider). The model already existed, redesign SURFACES it:** two layers, both character-keyed. Layer 1 = global `loadout` store (`critcalc:loadout`, `{weaponId,weaponRefinement,artifactSetId}`) = the "Roster loadout" (TB never read it — that's the gap). Layer 2 = per-tab `tabLoadout` override inside each planner tab, shadows L1 field-by-field (keeps "compare builds across tabs"). Loadout FEEDS the timeline (weapon `cdReset` procs, artifact/weapon buff windows). **Resolution:** planner's always-visible per-tab loadout chips (`RotationTimeline.svelte:1166-1200`, `.rp-loadout-rows`) stay UNCHANGED; retired modal DROPS its loadout dropdowns (pure picker); L1/Roster-default editing moves to the TB (Bench + Detail). Planner-only users lose nothing.

**Phase order (risk-sequenced):** 1 Foundations (extract `barGeometry.ts` from RotationTimeline; add `ownership` store — no visible change) → 2 Compare stacked bars (inside existing modal) → 3 Ownership ledger UI → 4 Shell reorg (Bench/Source-tabs/Stage-docked) → 5 Shared `CharacterGrid` extraction + planner non-modal conversion (RISKIEST, touches planner) → 6 Audition + responsive + full probe rewrite. Each phase gate-passing (`npx vitest run`, `npm run check`, `npm run lint`) + verify skill; phases 1&5 pixel-diff the planner (must be unchanged).
