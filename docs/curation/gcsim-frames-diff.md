## 4. Proposed application schedules

`+f` is frames from cast start to the hitmark. ⚓ **An empty cast column with an
empty streams column is the finding** — it is the positive statement that the cast
applies nothing, which the corpus has never been able to make (Xiangling's E, Hu
Tao's E, Itto's Q). ⚠️ An empty cast column with a stream beside it means something
quite different: everything this cast applies, it applies on a cadence.

`[icd]` marks a hit gcsim's ICD check blocked at the target; `[0U]` a hit that
carries no gauge at all (no check ran). ↻ Until the ICD cap round both read `[icd]`,
and two hits in one frame under one ability were married to ONE reading. A
blocked hit is still a NOMINAL
application and is still authored — C4: `icd.ts` decides whether one lands, this
list says what would.

Summon ticks are separated out because `interval` / `firstTickDelay` already model
them and ⛔ they are not re-authored here. ⚓ A stream counts as a tick only when
the ability DECLARES a summon: regularity alone is not enough, because a multi-hit
burst is evenly spaced too and belongs to the cast. **⚠️ regular, no authored
summon** flags the ambiguous ones for a human — either a multi-hit cast (author it
in the list) or a thing left in the world we have not modelled.

`gcsim cadence` is each cast stream's own ICD group (window / period / cap), read off
gcsim's tables the way §5 reads a tick series' — ⚠️ it is the RULE, not the applied
count; §4b lists the casts whose rule the schema default does not reproduce.
